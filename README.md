# AI-помощник для подготовки товарных описаний

Прототип сервиса на Python для генерации черновиков карточек товаров контрольно-измерительных приборов (КИП) через LLM API. Реализован уровень MVP согласно техническому заданию.

## Функционал
- Принимает данные о товаре в формате JSON через консольный интерфейс.
- Передает данные в LLM (DeepSeek V4 Flash через Bothub API).
- Формирует черновик карточки: SEO-заголовок, SEO-описание, структурированный список характеристик, поисковые запросы и commercial-блок для менеджера.
- Корректно обрабатывает отсутствие данных: не выдумывает характеристики, а явно указывает «данных нет» или запрашивает уточнение.
- Устойчив к ошибкам: корректно обрабатывает сбои API и невалидный ввод без падения скрипта.

## Структура
- `main.py` — основной скрипт с логикой консольного ввода, очистки ответа и запросами к API.
- `texts.py` — файл с системным промптом для LLM.
- `config.py` — файл с API-ключом (в репозитории **не представлен**).

## Анализ решения

### Что сработало
- **Stateless-архитектура:** История диалога принудительно очищается после успешной генерации каждой карточки. Это гарантированно предотвращает «галлюцинации» и смешивание характеристик разных товаров при пакетной обработке.
- **Надежный парсинг:** Реализован механизм считывания многострочного JSON до пустой строки, что решает проблему "разрезания" данных при вставке из буфера обмена в консоль.
- **Защита от Markdown:** Код автоматически очищает ответ LLM от обёрток ````json`, что предотвращает ошибки `json.loads`.

### Что не очень
- Консольный интерфейс неудобен для конечного пользователя (контент-менеджера). Копировать JSON из терминала менее эргономично, чем из веб-формы.

### Что бы ещё добавил в решение, если бы было больше времени
1. **Веб-интерфейс:** Реализовал бы простой UI на Streamlit или FastAPI + React, где контент-менеджер видит форму ввода слева и готовую карточку с кнопкой "Копировать" справа.
2. **Валидация на входе:** Добавил бы проверку входного JSON через библиотеку `pydantic` *до* отправки запроса в LLM. Это сэкономило бы токены и время, мгновенно указывая пользователю на синтаксические ошибки.
3. **Пакетная обработка:** Добавил бы возможность загружать Excel/CSV файл с десятками товаров и обрабатывать их асинхронно (`asyncio`), сохраняя результаты в новый файл.

### Как оценил качество решения
Задание считаю выполненным в полном объеме. Прототип устойчив, промпт успешно предотвращает выдумывание технических характеристик, а код соответствует требованиям безопасности (API-ключ вынесен из репозитория). Решение готово к использованию как MVP и имеет четкий план масштабирования до продакшена.
